# 2026-07-26 学习笔记

## 核心概念（6个）

### 1. Fuzz（模糊测试）
用极端/变态的输入测试程序的鲁棒性——超长、超短、类型不对的输入，看程序会不会崩。崩了就可能是个漏洞。

### 2. AFL++ vs libfuzzer
- **AFL++**：American Fuzzy Lop的增强版，独立运行，自动变异输入
- **libfuzzer**：Google的fuzz引擎，嵌入在代码里（用`LLVMFuzzerTestOneInput`入口），和ASAN一起编译进去

### 3. ASAN（AddressSanitizer）
编译时插入的"内存警察"。不开ASAN时，小溢出可能悄悄执行完不崩（但内存已被破坏）；开了ASAN，任何越界立刻被抓住并报告精确位置。

### 4. Crash ≠ 漏洞
- **Crash**：程序崩溃（段错误等），是现象
- **漏洞**：能被攻击者利用来造成安全危害的bug
- 每个漏洞都会导致crash，但不是每个crash都能被利用（可能无法控制、或只能DoS）

### 5. CVE / CNA / 流程
- **CVE**：全球统一的漏洞身份证编号（如CVE-2024-12345）
- **CNA**：CVE编号授权机构（MITRE是总管，Canonical是Ubuntu母公司也是CNA之一）
- **流程**：发现漏洞 → 报告给项目/CNA → CNA确认分配CVE编号 → NVD/CNVD收录 → 公开

### 6. Harness（测试桩）
你写给fuzzer的一小段代码，告诉fuzzer"把变异数据传给我，我来调被测函数"。`LLVMFuzzerTestOneInput(data, size)` 就是libfuzzer的标准入口——libfuzzer自己提供main()，自动生成变异数据，你只需关心"拿data和size怎么调目标函数"。
