## 一、本日核心成果

### ⭐ 成果 1：MindSpore load_checkpoint 堆缓冲区溢出（CWE-787）——变体审计挖出的全新漏洞，比 DoS 严重

- **dims=[2]（期望 8 字节）+ content=256 字节 → 8 字节缓冲被写 256 字节 → 堆破坏**
- 279 字节恶意 .ckpt → `load_checkpoint` **正常返回**，随后 tensor 析构时 `free(): invalid next size (fast)` 崩溃
- 源码根因（master `ccsrc/pybind_api/ir/tensor_py.cc`）：
  - `CopyFromBuffer()` 的 **`dst_size` 参数完全没被读取**
  - `memcpy_s(dst_ptr, remain_size, ...)` 把 **攻击者控制的内容长度** 当目标缓冲大小 → 安全函数被绕过
  - `tensor_content` 长度从不校验是否匹配 dims → **与 DoS 同根因，两种表现**
- **2.8.0 + 2.10.0（最新）+ master 均未修**；越界 ≥24 字节稳定崩溃
- 影响：内存破坏（潜在任意代码执行/可靠 DoS），HF/ModelScope 投毒模型供应链

### 成果 2：MindSpore load_checkpoint 内存放大 DoS（2.8.0 与最新 2.10.0 均未修）

- **32 字节**恶意 .ckpt → MindSpore 尝试分配 **40GB**（放大 12.5 亿倍）
- 根因：.ckpt protobuf 的 `tensor.dims` 不校验是否匹配实际数据 → C++ `ConvertBytesToTensor` 按攻击者 dims 分配
- 实测证据（2.8.0 与 2.10.0 输出一致）：
  ```
  [WARNING] Try to alloca a large memory, size is:40000000000
  ```
- 攻击面：HuggingFace / ModelScope 投毒模型，任何 load_checkpoint 用户触发
- 影响范围：CVE-2026-50144 之前的**已知未修漏洞，无 CVE 编号**，最新版仍受影响 → 可上报华为/CNVD

### 成果 3：NCNN ParamDict 参数解析两漏洞（一个已修，一个**至今未修**）

**2a. CVE-2026-50144（负 ID 堆越界写）——复现 + 补丁 diff 闭环**
- 根因：参数 `id` 为负值时跳过 `id >= NCNN_MAX_PARAM_COUNT` 检查 → 负索引越界写
- 修复（commit 5a0288f2）：`if (id < 0 || id >= ...)`
- 本地对比：漏洞版 20260526 + ASAN → SEGV on WRITE @paramdict.cpp:612；master → 优雅拒绝

**2b. ⭐ 96B NULL 解引用（**最新代码仍未修复**，潜在新 CVE）**
- 根因：数组分支 `len` 完全未校验 → `Mat::create(len)` 分配失败返回 NULL → `dr.read(NULL)` → SIGSEGV
- **关键**：CVE-2026-50144 的补丁（防负 ID）**管不到**这个 len 分支 → 同文件、同家族、未打补丁
- 实测：96 字节 .parambin 在 **master（当前最新）** 上崩溃（SIGSEGV exit 139；ASAN 报 allocation-size-too-big @paramdict.cpp:591）
- text 格式同款（len=INT32_MAX → abort exit 134）
- 防御不对称证据：兄弟文件 modelbin.cpp 有 5 处 `Mat::empty()` 防护，paramdict 数组分支 0 处

## 二、方法论进展：补丁 diff 挖法（学到一套高效挖法）

```
拿已知 CVE 修复 commit → diff 新旧源码 → 定位"单行检查"改动
→ 判断只堵了一个口子 → 顺藤摸瓜找同文件没打补丁的分支 → 找到未修变体
→ CVE 修复 = 免费漏洞地图，顺着修复找同类，比从零挖快 10 倍
```
96B 漏洞就是靠这套方法（从 CVE-2026-50144 的修复出发）找到的。
