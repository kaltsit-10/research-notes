# NCNN text 层头漏洞 — 提交操作指引（2026-08-07）

## 渠道决策：GHSA 为主，TSRC 为备

| 维度 | GitHub Security Advisory (PVR) | 腾讯 TSRC |
|------|------|------|
| **推荐度** | 🥇 **主推** | ⚠️ 备选 |
| **先例** | CVE-2026-50144 正是走 GHSA（GHSA-jxmc-3mv6-7pwr），CVE 由 GitHub 分配 → ncnn 官方接受此渠道 | 无 ncnn 漏洞先例；TSRC 表单面向 Web/APP（漏洞URL、APP名称字段），对 C++ 开源库不友好 |
| **上报人可见性** | 需要 GitHub 账号；匿名/昵称署名（Credits） | 需要 TSRC 账号（QQ/微信登录），实名关联 |
| **CVE 获取** | GitHub 作为 CNA 可代申请 CVE（约 72h 审核，先 reserved 后 publish） | TSRC 不直接发 CVE，需厂商内部流程 |
| **AI 报告风险** | 无强制"AI 报告"标签；内容完整即可 | TPSA26-03 要求人工验证+截图，未满足直接驳回；超 5 个无效报告拉黑 |
| **90 天惯例** | 协调披露惯例，报告者可声明时间表 | 无固定披露窗口概念 |
| **备注** | ncnn **无 SECURITY.md**（已查证），但 PVR 与 SECURITY.md 独立 | TSRC 英文政策页面可达（en.security.tencent.com/policy） |

**结论**：走 GHSA（`https://github.com/Tencent/ncnn/security/advisories/new`）。理由：与 CVE-2026-50144 完全同渠道，ncnn 官方已证明接受此渠道并能产出 CVE；TSRC 表单是 Web 导向，且 AI 报告规范更严苛。

## 操作步骤（GHSA 渠道）

### 1. 确认 ncnn 是否开启 Private Vulnerability Reporting

- 浏览器打开 `https://github.com/Tencent/ncnn` → **Security** 标签页
- 若页面有 **"Report a vulnerability"** 按钮 → PVR 已开启，直接进入步骤 2
- 若无该按钮 → PVR 未开启，走**备选路径**（见下）

> 注意：仓库 `security_and_analysis` API 字段返回 `null`（未认证视角），需人工确认。ncnn 无 SECURITY.md，若 PVR 未开启，GitHub 官方建议是**发一个 issue 询问维护者首选安全联系渠道**。

### 2. 提交私密报告

- 入口：`https://github.com/Tencent/ncnn/security/advisories/new`
- **必填**：Title + Description（其余字段鼓励填写）
- 把 [GHSA 英文稿](GHSA-NCNN-text-layer-header-上报-2026-08-07.md) 中：
  - `## Title` → 粘贴到 Title 框
  - `## Description` → 粘贴到 Description 框
  - `Affected products` / `Severity` / `Weaknesses` / `Credits` 各字段按表格填
- 点击 **Submit report** → 维护者立即收到通知，你自动成为该 advisory 的 collaborator 并获 pending credit
- 可选：点 **Start a temporary private fork** 用于协作修复（仅维护者可合并）

### 3. 后续协调

- 维护者收到后进入 **Triage** 状态，可接受为 draft / 评论索要信息 / 关闭
- 只有仓库 admin（维护者）能发布 advisory；你作为报告者只能协作与建议时间表
- 维护者可点 **Request CVE** 由 GitHub 代申请 CVE 编号（约 72h 审核）
- 建议在报告中声明 **90 天协调披露窗口**，到期前不公开

### 备选路径（若 PVR 未开启）

1. 在 ncnn 仓库发 issue 询问安全联系渠道（GitHub 官方推荐做法）
2. 或联系维护者：nihui 等通过 GitHub 公开渠道
3. 或改走 TSRC 渠道（见 [TSRC 中文稿](TSRC-NCNN-text层头-上报-2026-08-07.md)）

## ⚠️ 关键合规提醒

### 1. AI 辅助报告声明（TSRC 渠道必须，GHSA 建议）
- 本漏洞由 AI 辅助发现（静态审计 + 变异 PoC 生成）
- **已人工验证**：2026-08-07 在 WSL2 实机编译 master `a4d2ea1`，三个变体全部人工复现（SIGABRT / ASan heap-buffer-overflow / 8GB 挂起）
- 附件中**必须有截图**（崩溃输出、ASan 报告、正常对照），否则 TSRC 直接驳回

### 2. 保密红线（用户既定约束）
- **PoC 在腾讯修复前不得公开**——本材料只给厂商，不是博客/论文材料
- 上报前需再次确认：是否已提供"人工验证截图"（这是 TPSA26-03 的硬性要求）
- 你的真实身份信息（姓名/学号）**不要**出现在提交中，除非渠道强制实名（TSRC 用 QQ 登录本身就是实名）；ncnn 走 GHSA 用 GitHub 用户名/昵称（Credits）即可，不强制实名

### 3. 上报前的最终复核清单
- [ ] 再次 `git pull` ncnn master，确认 **text 层头漏洞仍未修复**（2026-08-07 时点为 a4d2ea1，未修）
- [ ] PoC 三个文件可运行、输出与材料一致
- [ ] 截图已生成并放入附件
- [ ] 确认不引用已推翻的 CNVD-2026-23196
- [ ] 确认"漏洞 1（96B）"不混入本报告（那是已公开的促修复项，只报 text 层头这一个新漏洞）

### 4. 预期结果与备选
- 走 GHSA → 大概率获得 GHSA 编号 + GitHub 分配 CVE（参照 CVE-2026-50144）
- 若维护者判定为 CVE-2026-50144 的变体/重复 → 要求其说明理由，并引用"根因不同（net.cpp 层头 vs paramdict.cpp 负 ID）+ 修复不覆盖 + master 实测仍在"
- 若 GHSA 渠道受阻 → 备选 TSRC 渠道；再备选：向 CNVD 提交（需厂商侧配合确认）
