# NCNN 参数解析两处未修复漏洞——上报材料

> 组件：Tencent/ncnn（开源推理框架，微信/QQ 等腾讯业务内嵌）
> 日期：2026-08-07
> 复现环境：WSL2 Ubuntu 22.04 x86_64，ncnn master（20260526 标签之后的最新提交）
> 结论：**一个独立未上报新漏洞 + 一个已公开未修复漏洞**（text 版层头解析 = 独立未上报，本材料主报送；bin 版 NULL 解引用 = 已有第三方公开 PoC，仅促修复），均可由攻击者可控模型参数文件远程触发

| 项 | 漏洞 1（bin 版） | 漏洞 2（text 版） |

| ⚠️ 公开 PoC | **已有**（HF `currentlyawey/ncnn-parambin-null-deref-dos`，与本次复现 100% 对应）→ **原创性不成立，仅促修复** | **无任何公开记录**（05-28 CVE 修复不碰 net.cpp；07-22 master 实测仍崩溃）→ **独立未上报** |

- 漏洞 2（text 层头）为独立未上报新漏洞，是**本材料主报送对象**
- 归档初版曾引用的"CNVD-2026-23196"经核实**疑似串号捏造**（同号 CVE-2026-23196 实为 Linux 内核 HID 漏洞），已剔除，**不作为任何公开状态证据**

## 二、漏洞描述

### 2.1 漏洞 1：bin 版数组分支 len 未校验 → NULL 解引用（CWE-476）

`ParamDict::load_param_bin` 解析 `.parambin` 的数组参数（标记 `id = -23300` 起）时：

```cpp
// src/paramdict.cpp:577-599（master，未修）
else if (is_array)
{
    int len = 0;
    nread = dr.read(&len, sizeof(int));          // len 完全未校验（攻击者可控）
    ...
    d->params[id].v.create(len);                  // len=INT32_MIN → size_t 符号扩展 → ~18EB 分配
    float* ptr = d->params[id].v;                 // fastMalloc 失败 → data=NULL
    nread = dr.read(ptr, sizeof(float) * len);    // fread 写 NULL → SIGSEGV
}
```

- `len = 0x80000000`（INT32_MIN）传入 `Mat::create(int)`，内部 `(size_t)w * elemsize` 符号扩展成 ~18EB → `fastMalloc`（posix_memalign）失败返回 NULL
- **`Mat::create` 不检查分配失败**（对照：兄弟文件 `modelbin.cpp` 每次 create 后都有 `if (v.empty())` 检查，`paramdict.cpp` 缺失——**同一团队的防御模式没打全**）
- 下一句 `dr.read(ptr, ...)` 向 NULL 写 → **SIGSEGV**

### 2.2 漏洞 2：text 版层头 token 数不校验 → top_count 越行读取（CWE-787/CWE-755/CWE-789）

`Net::load_param` 解析 `.param` 层定义行时：

```cpp
// src/net.cpp —— Net::load_param 层头解析（master a4d2ea1，行号随 commit 变化，以函数名为准）
SCAN_VALUE("%255s", layer_type)
SCAN_VALUE("%255s", layer_name)
SCAN_VALUE("%d", bottom_count)
SCAN_VALUE("%d", top_count)
```

- **不校验层行是否包含全部 4 个字段**。若层行只有 3 个 token（如 `ReLU 0 0`），`top_count` 从**下一行的攻击者数据**读取
- `top_count` 是攻击者可控的任意 int，随后直接用于：
  ```cpp
  // src/net.cpp —— master a4d2ea1 实测行号（随 commit 变化，以函数名为准）
  // Net::load_param 层头 SCAN_VALUE 块 = 1394-1397
  layer->tops.resize(top_count);   // =1456；负值 → vector 异常；巨大值 → 巨型分配
  Blob& blob = d->blobs[blob_index];  // =1459；越界 → 堆越界读写（ASan 命中 1464）
  ```
- 三种攻击形态（实测）：

| 越行 top_count | 行为 | 证据 |
|---|---|---|
| 负值（-5/-23300 等） | `tops.resize(负)` → `vector::_M_default_append` 抛 `std::length_error` → **未捕获异常 → SIGABRT** | gdb catch throw 确认 |
| 正大值（1000000） | blob 访问越界 → **堆缓冲区越界读写** | ASAN `heap-buffer-overflow @ net.cpp:1464` |
| 正巨大（2000000000） | `tops.resize(2e9)` → ~8GB 分配 → **内存耗尽/挂起** | 实测超时 |

## 四、根因定位

### 漏洞 1 根因

- `ParamDict::load_param_bin` 数组分支：**`len` 读取后无任何校验**（无 `len <= 0`、无 `Mat::empty()` 检查）
- `Mat::create` 分配失败返回 NULL 但不报错，调用方直接使用 → NULL 写
- 对比 `modelbin.cpp` 的防护模式（`if (v.empty())` 5 处），`paramdict.cpp` 完全缺失 → **防御不对称**

### 漏洞 2 根因

- `Net::load_param` 层头：**`SCAN_VALUE` 连续读取 4 字段不校验 token 数**，`top_count` 可越行读取攻击者值
- 缺一个"层行字段完整性"校验（如检查 scan 是否消费完本行）

### 与 CVE-2026-50144 的关系

- CVE-2026-50144 是**负 ID 越界写**（`id < 0` 未检查），修复 commit `5a0288f2` 加了 `id < 0 || id >= NCNN_MAX_PARAM_COUNT`
- 该修复**无法覆盖**两个新漏洞：漏洞 1 的 `id=0` 合法（问题在 `len`）；漏洞 2 的 `id` 合法（问题在层头 `top_count`）

## 五、影响评估

| 维度 | 漏洞 1（bin） | 漏洞 2（text） |
|---|---|---|
| 攻击者可控性 | `.parambin` 完全可控 | `.param` 完全可控 |
| 可达性 | 任意调用 `Net::load_param_bin` 的加载路径（`Net::load` / `load_param_bin`） | 任意调用 `Net::load_param` 的加载路径 |
| 是否需先通过校验 | 否（文件即入口） | 否（文件即入口） |
| 后果 | 确定性 SIGSEGV（DoS） | SIGABRT / 堆越界 / 内存耗尽（DoS + 潜在内存破坏） |
| 供应链场景 | ncnn 广泛用于移动端 AI 推理（微信、QQ、短视频等），恶意/被投毒模型文件分发即触发 | 同左 |

- **CWE-476（NULL 解引用）**：确定性进程崩溃，服务端/客户端均可被远程 `.parambin` 击溃（DoS）
- **CWE-787（堆越界）**：text 版 top_count=1e6 变体已由 ASAN 证实 heap-buffer-overflow，可能发展为任意读/写原语（需进一步利用）
- **CWE-755（未捕获异常）**：`std::length_error` 未处理 → abort，即使 C++ 异常被禁用（-fno-exceptions）也会 terminate
- **CWE-789（内存耗尽）**：top_count=2e9 → 8GB 分配挂起

**CVSS 粗略估算（未精确计算）**：攻击向量网络（供应链）/低复杂度/无权限/需用户加载恶意模型文件。DoS 类约 6.5-7.5（中高），若堆越界可进一步利用则可能 8.0+。建议以厂商实际评分为准。

## 六、修复建议

### 漏洞 1（bin 版）

```cpp
else if (is_array)
{
    int len = 0;
    nread = dr.read(&len, sizeof(int));
    if (len <= 0)                          // 新增：拒绝非正长度
    {
        NCNN_LOGE("invalid array length %d", len);
        return -1;
    }
    d->params[id].v.create(len);
    if (d->params[id].v.empty())           // 新增：分配失败检查（对齐 modelbin.cpp 防御模式）
    {
        NCNN_LOGE("create array failed");
        return -1;
    }
    ...
}
```

### 漏洞 2（text 版）

```cpp
// 层头解析处：校验 top_count/bottom_count 合理性，阻止越行读取
SCAN_VALUE("%255s", layer_type)
SCAN_VALUE("%255s", layer_name)
SCAN_VALUE("%d", bottom_count)
SCAN_VALUE("%d", top_count)
if (bottom_count < 0 || top_count < 0 ||
    bottom_count > MAX_LAYER_BLOB_COUNT || top_count > MAX_LAYER_BLOB_COUNT)   // 新增
{
    NCNN_LOGE("invalid bottom/top count %d %d", bottom_count, top_count);
    return -1;
}
```
