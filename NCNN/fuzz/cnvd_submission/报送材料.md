## 二、详细代码分析过程

### 2.1 定位与调用链

受影响函数：`ncnn::Net::load_param_bin(const DataReader&)`，文件 `src/net.cpp`。
它解析 `.parambin`（ncnn 二进制模型参数文件，TensorRT/ONNX 导出后的通用部署格式），
是 ncnn 加载模型的**两个入口之一**（另一入口为文本 `.param` 的 `load_param`）。
任何调用 `Net::load()` / `Net::load_param_bin()` 处理不可信文件的应用程序均受影响；
ncnn 被广泛内嵌于微信、QQ 及大量移动/桌面应用。

### 2.2 缺陷代码（upstream master `946fe3f`，实测行号）

**① 文件头 `layer_count` / `blob_count` 仅做非正校验，无上限**（L1699-1709）：

```cpp
READ_VALUE(layer_count)
READ_VALUE(blob_count)
if (layer_count <= 0 || blob_count <= 0)      // L1702：仅非正校验，无上限
{
    NCNN_LOGE("invalid layer_count or blob_count");
    return -1;
}
d->layers.resize(layer_count);                // L1708：2^30 等巨大值 → ~137GB 分配
d->blobs.resize(blob_count);                  // L1709
```

**② 每层 `bottom_count` / `top_count` 零校验**（L1762-1769）—— 负值/巨大值直达
`std::vector::resize()`（L1803/L1816），负值抛未捕获的 `std::length_error` → `std::terminate()`；
巨大值触发多 GB 分配 / `std::bad_alloc`：

```cpp
for (int i = 0; i < layer_count; i++)
{
    int typeindex;
    int bottom_count;
    int top_count;
    READ_VALUE(typeindex)                     // L1767：攻击者可控
    READ_VALUE(bottom_count)                  // L1768
    READ_VALUE(top_count)                     // L1769
    ...
    layer->bottoms.resize(bottom_count);      // L1803：无符号/上限校验
```

**③ blob 索引越界读写（本漏洞核心，CWE-125/787）**（L1803-1830）：

```cpp
layer->bottoms.resize(bottom_count);
for (int j = 0; j < bottom_count; j++)
{
    int bottom_blob_index;
    READ_VALUE(bottom_blob_index)             // L1807：攻击者可控 int32，零校验

    Blob& blob = d->blobs[bottom_blob_index]; // L1809：OOB 读（CWE-125）

    blob.consumer = i;                        // L1811：OOB 写（CWE-787）← ASan 证实 WRITE
    layer->bottoms[j] = bottom_blob_index;
}
// top_blob_index 处理同构（L1816-1830，blob.producer = i）
```

`d->blobs` 在 L1709 已按文件头 `blob_count` resize，但 L1809/L1822 的索引访问处
**没有任何 `0 <= idx < blob_count` 范围校验**，攻击者构造的 `bottom_blob_index` /
`top_blob_index`（int32 全范围可控）直接用于数组下标。

**④ 同函数附加缺陷（随 #6922 一并修复，非本报送主项）**：L1848
`const int psh_step = shape_hints.w / top_count;` —— 当 `top_count == 0` 且存在
shape-hint（id 30）时整数除零（CWE-369）。

### 2.3 与文本路径（`load_param`）的不对称（根因家族）

文本 `.param` 路径通过 blob 名字查表（`find_blob_index_by_name()`）+ `-1` 兜底
**间接限界**；二进制路径直接裸读整数、零防护——同一解析器家族中"一处有防护、
一处裸奔"的典型不对称缺陷（兄弟漏洞）。

### 2.4 与既有 CVE 的区分

| 项 | CVE-2026-50144（已修） | 本漏洞（未修） |
|---|---|---|
| 位置 | `src/paramdict.cpp` `ParamDict::load_param`（参数 id 负值） | `src/net.cpp` `Net::load_param_bin`（blob 索引） |
| 修复 commit | `5a0288f2`（2026-05-28，仅 paramdict.cpp） | 无（上游未修；fork PR #6922 待合入） |
| 机制 | 负 id × sizeof(Param) 越界写 | blob 索引 × sizeof(Blob) 越界读+写 |
