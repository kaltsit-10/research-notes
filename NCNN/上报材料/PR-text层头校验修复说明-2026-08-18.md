## 三、commit message（自底向上 3 个 commit）

**commit 1 `0f3dc15`**（BIN 守卫）：
```
fix out-of-bounds blob index and unvalidated counts in load_param_bin
```

**commit 2 `31341ba`**（TEXT 守卫）：
```
validate layer header counts and resource bounds in load_param

Net::load_param (text .param) reads attacker-controlled layer_count/
blob_count and per-layer bottom_count/top_count with no upper bound and
no sign check on the per-layer counts. A crafted file can:

1. set blob_count huge -> d->blobs.resize() allocates ~137GB and OOMs
   before the layer loop even starts (ASan: allocator OOM)
2. set top_count/bottom_count negative -> layer->tops.resize(-1) throws
   std::length_error -> uncaught terminate
3. set bottom_count/top_count to INT_MAX -> multi-gigabyte resize ->
   std::bad_alloc / OOM

Mirror the guards added in the binary path:
- reject layer_count/blob_count <= 0 or > 1M right after the header
  read, before any allocation
- reject negative or > 1M bottom_count/top_count per layer
```

**commit 3 `408f6df`**（除零修复）：
```
skip shape-hint processing when top_count is zero

both load_param and load_param_bin divide by top_count when a nonempty
shape-hint parameter (id 30) is present. the new per-layer count guards
allow top_count == 0, so a crafted file combining top_count == 0 with a
nonempty shape hint drives an integer division by zero (FPE). skip the
shape-hint block when top_count is zero; zero-output layers are otherwise
valid and must not be rejected.
```

三个 commit 叠加即完整补丁，GitHub PR diff 显示为 master→`408f6df` 的 42+/6-。
