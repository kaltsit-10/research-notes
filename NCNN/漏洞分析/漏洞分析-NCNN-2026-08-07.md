# NCNN 参数解析漏洞分析（2026-08-07 本地复现）

> 环境：WSL2 Ubuntu 22.04 x86_64，gcc 11.4，ASAN
> 目标：Tencent/ncnn `ParamDict::load_param() / load_param_bin()`（src/paramdict.cpp）与 `Net::load_param()`（src/net.cpp）
> 结论：**三个漏洞**。CVE-2026-50144 已修复；**96B NULL 解引用未修（bin 版）**；**text 版层头解析漏洞未修（新增确认，与 96B 不同根因）**

---

## 一、背景：ParamDict 参数格式

ncnn 的 `.param`（文本）和 `.parambin`（二进制）文件包含每个算子的参数，由 `ParamDict::load_param` / `load_param_bin` 解析：

- 记录以 `id` 开头：
  - `id = -233` → 终止符
  - `id <= -23300` → **数组标记**，解码为 `id = -id - 23300`，后续读数组长度 `len`
  - `id <= -23400` → 字符串标记
  - 其他 → 普通值（读一个 float 存到 `d->params[id].f`）
- `d->params` 是 `Param[NCNN_MAX_PARAM_COUNT]`（本构建 = 32）数组

**共同根因**：攻击者可控的 `id` / `len` 在用作数组索引 / 分配大小之前，校验不完整。

---

## 二、CVE-2026-50144：负 ID → 堆越界写（已修复）

### 漏洞

负 ID（如 `-5`，不是数组标记 `<=-23300`、不是 `-233`）会跳过 `id >= NCNN_MAX_PARAM_COUNT` 检查，进入 else 分支：

```cpp
// 漏洞版 paramdict.cpp:612
else
{
    nread = dr.read(&d->params[id].f, sizeof(float));  // id=-5 → 越界写 params[-5].f
```

### 修复 diff（commit 5a0288f2，两处：text ~280 / bin ~534）

```diff
-        if (id >= NCNN_MAX_PARAM_COUNT)
+        if (id < 0 || id >= NCNN_MAX_PARAM_COUNT)
         {
             NCNN_LOGE("id < NCNN_MAX_PARAM_COUNT failed (id=%d, NCNN_MAX_PARAM_COUNT=%d)", id, NCNN_MAX_PARAM_COUNT);
             return -1;
         }
```

### 本地复现

PoC：`poc_negid.parambin`（36 字节）——普通层头 + `id=-5` + value + `-233` 终止。

| 构建 | 结果 |
|------|------|
| **漏洞版 20260526 (e54f7b1)** + ASAN | `SEGV on WRITE`，栈：`ParamDict::load_param_bin` @ paramdict.cpp:612 |
| **master（已修）** | `id < NCNN_MAX_PARAM_COUNT failed (id=-5)` → ret=-1 优雅拒绝 |

### 教训（补丁 diff 挖法）

1. 拿到修复 commit → diff 旧/新版本 → 定位**单行检查**的改动
2. 单行检查通常意味着"边界只查了一半"——问自己：**另一半边界还缺什么？**
3. 顺着同款代码（text / bin 两处）找**未打的补丁**（不对称）

## 三、96B NULL 解引用：len 未校验 → 分配失败后空指针写（**未修复**）

### 漏洞（paramdict.cpp 数组分支，~581 行）

```cpp
else if (is_array)
{
    int len = 0;
    nread = dr.read(&len, sizeof(int));          // len 完全未校验！
    ...
    d->params[id].v.create(len);                  // len=INT32_MIN → 符号扩展到 exabyte 级分配

    float* ptr = d->params[id].v;                 // fastMalloc 失败 → data=NULL
    nread = dr.read(ptr, sizeof(float) * len);    // fread 写入 NULL → SIGSEGV
```

- `len = 0x80000000`（INT32_MIN）→ `Mat::create()` 符号扩展成 `size_t` → ~18EB 分配 → 失败返回 NULL，**create() 不报错**
- 下一句 `dr.read(NULL)` → fread 向 NULL 写 → **SIGSEGV**
- **修复 CVE-2026-50144 的 `id<0` 检查管不到这里**（id 合法=0，是 len 的问题）

### 不对称：兄弟文件 modelbin.cpp 有 5 处防护，paramdict 没有

`modelbin.cpp` 每次 `Mat::create()` 后都有 `if (v.empty())` 检查；`paramdict.cpp` 的 text / bin 数组分支都缺。**同一团队的防御模式没有打全。**

### 本地复现（当前 master，最新版）

PoC：`poc96.parambin`（96 字节）——ReLU 层头 + 数组标记 `id=-23300` + `len=0x80000000` + 64 填充。

| 构建 | 结果 |
|------|------|
| **master（已修 CVE-2026-50144）** 普通版 | **Segmentation fault（exit 139）** |
| **master + ASAN** | `allocation-size-too-big 0xfffffffe00000044`，栈：`ParamDict::load_param_bin` @ paramdict.cpp:591 |

**这是当前最新代码里仍可触发的崩溃 = 可上报的新发现（CWE-476，疑似未分配 CVE）。**

### PoC 二进制布局（96 字节）


## 三.5、⭐ text 版真根因：层头 token 数不校验（CWE-787/CWE-755，08-07 晚实测修正）

**修正此前"text 版同款（paramdict 数组 len）"的旧结论**——实测隔离证明：
- 完整层头 + INT32_MAX 数组 → `read array element failed → ret=-1`（**不崩**）。text 版 paramdict 数组分支有"元素读取失败即返回"的保护，与 bin 版不同，**不是独立漏洞**。
- 真正根因在 `Net::load_param` **层头解析**（net.cpp:1139-1142）：`SCAN_VALUE` 依次读 `type/name/bottom_count/top_count`，**不校验层行 token 数**。
- 若层行只有 3 个 token（如 `ReLU 0 0`），第 4 个 `top_count` 会**越行读取下一行的攻击者值** → 三类攻击：

| 越行 top_count | 行为 | 证据 |
|---|---|---|
| 负值（-5/-23300/-1000000） | `layer->tops.resize(负)` → `vector::_M_default_append` → **length_error → SIGABRT** | gdb catch throw 确认 |
| 正大值（1000000） | `d->blobs[blob_index]` 越界 → **CWE-787 堆缓冲区溢出**（读越界 `Blob.name` string） | ASAN `heap-buffer-overflow @ net.cpp` |
| 正巨大（2000000000） | `tops.resize(2e9)` → ~8GB 分配 → **内存耗尽/挂起 DoS** | 实测超时 |

- PoC：`poc_text_layerheader.param`（最小 abort 触发，41B）、`poc_text_header.param`（48B）、`poc_text_oob.param`（38B）、`poc_text_oom.param`（41B）
- **修复建议**：层头解析校验 `bottom_count`/`top_count` 在合理上界内（或 `scan` 行结束检查），阻止越行读取；与 CVE-2026-50144 修复同模式（`id<0` 检查）。
- **独立于 96B**：96B 在 paramdict.cpp 数组分支（len 未校验 → NULL 写），text 版在 net.cpp 层头（token 数 → 越行读取）。两个未修漏洞，两条根因。

## 四、上报建议

- **96B NULL 解引用**：`ParamDict::load_param_bin()` 数组分支，`len` 未校验（无 `len<=0` / `Mat::empty()` 检查）→ 上报 ncnn（腾讯）+ CVE 流程。与已修的 CVE-2026-50144 同文件、同家族、未打补丁。
- **text 版层头解析**（本日新增确认）：net.cpp 层头 token 数不校验 → top_count 越行 → abort/堆越界/内存耗尽。独立根因，同样未修。
- 相关已知问题：ncnn issue #6382（`Net::load_param` 失败 `continue` → nullptr 崩溃 + 泄漏），独立缺陷。
