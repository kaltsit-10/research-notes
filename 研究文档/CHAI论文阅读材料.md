# CHAI 论文阅读材料——《Command Hijacking against Embodied AI》

> **CHAI = Command Hijacking against embodied AI（对具身AI的命令劫持）**
> arXiv:2510.00181 · UC Santa Cruz + Johns Hopkins · 已投 IEEE SaTML 2026
> 这是你主线（ONNX fuzz）之外，最该理解的"另一类威胁"：**不碰代码，只放一块牌子就能劫持机器人**。

---

## 一、论文在说什么（一句话）

攻击者**不用黑进任何软件**，只需要在机器人的摄像头视野里**放一块写着文字的牌子/海报**，就能让机器人"听懂"并执行恶意指令——比如让无人机在敌方区域降落、让自动驾驶汽车冲进人行横道。

**这是"物理世界 + 提示注入"的结合**：人类可读的文字，同时是给 LVLM（大视觉语言模型）看的恶意提示。

---

## 二、为什么这篇和你高度相关

你的主线是在"AI 引擎底层"挖漏洞（ONNX Runtime 反序列化），攻击**软件**。
CHAI 展示的是具身 AI 的**另一条攻击链**：

```
主线（你的）： 恶意 .onnx 模型文件 → 引擎解析 → 内存崩溃/代码执行
CHAI（这篇）： 场景里的一块牌子  → LVLM 视觉理解 → 输出恶意指令 → 机器人执行
```

两条线都能搞瘫一台具身 AI 系统，但入口完全不同：一个打**数据面**，一个打**物理面**。

---

## 三、攻击流程（5 步）

```
[1] 攻击者确定目标：LVLM 驱动的机器人/无人机/自动驾驶
[2] 黑盒查询目标 LVLM（只能调 API，看不到权重）
[3] 用一个"攻击者 LLM"在 token 空间里搜索 → 生成一批高成功率文字提示（字典）
[4] 双重优化：同时调"牌子写什么"和"牌子长什么样"（颜色/字体/大小/位置）
[5] 打印出来贴到物理场景 → 机器人经过 → 被骗 → 执行恶意命令
```

关键点：攻击者**不需要任何模型内部信息**，纯黑盒，只靠反复 query + 观察输出。

---

## 四、核心创新：双重优化（Dual Optimization）

```
攻击参数 π = ( 语义内容 D  ,  视觉实现 Θ )
              牌子写什么      颜色/字体/大小/位置/角度

目标：最大化 P( LVLM 输出恶意指令 | π )

方法：交叉熵法（Cross-Entropy Method）
     —— 黑盒随机全局优化器（不是梯度！因为看不到模型内部）
     反复采样 → 保留表现好的 → 集中采样 → 逼近最优
```

**和你的 FGSM 对比**：FGSM 用 `x.grad.backward()` 拿到精确梯度（白盒）；
CHAI 拿不到梯度，只能"猜 + 淘汰"，用统计方法逼近最优解。

---

## 五、"命令层"是什么（这篇论文最重要的概念）

LVLM 驱动的机器人，决策链通常分两层：

```
感知层：LVLM 看摄像头画面 → 输出一段中间文本（"前方是十字路口"）
                                            ↑ 这就是"命令层/中间文本"
控制层：下游控制器把这段文本翻译成物理动作（刹车/转向/降落）
```

- **传统攻击打感知层**：让模型"看错"（把停止标志看成限速牌）——目标只是识别错。
- **CHAI 打命令层**：让模型"说错话"——输出一段**明确、可执行的恶意指令文本**，下游控制器会**忠实执行**。

> 打个比方：
> 感知层攻击 = 让接待员认错人（看了但判断错）
> 命令层攻击 = 让接待员说出"请带他去金库"（直接下达危险指令）

因为控制层默认"信任"中间文本，所以劫持命令层 = 劫持整台机器人的行为。

## 六、实验结果（记住这些数字）

| 场景 | 攻击成功率 (ASR) |
|------|-----------------|
| CloudTrack（无人机目标跟踪） | 最高 **95.5%** |
| DriveLM（自动驾驶） | **81.8%** |
| 无人机紧急降落 | **68.1%**（AirSim 环境最高 92%） |
| **真实物理机器人小车** | ≥ **87%**（多种光照/视角下） |

- 比此前 SOTA 文字攻击 **SceneTAP 强最多 10 倍**
- **通用对抗标牌**：对未见过的场景也有 >50% 成功率（GPT-based 场景 >70%）
- 跨语言有效：英语、中文、西班牙语、甚至混合语
- 恶劣天气下依然有效

## 七、和 SceneTAP 的区别（前置工作）

| | SceneTAP（旧） | CHAI（新） |
|---|---|---|
| 文字生成方式 | LLM 指令驱动（让 LLM 想文案） | 基于优化的黑盒搜索 + 双重优化 |
| 攻击针对性 | 每张图单独生成 | 对一组场景做**通用**对抗标牌 |
| 物理实现 | 能打印但没做物理验证 | 真实物理小车验证 ≥87% |
| 核心 | 场景一致的文字排版 | 命令层劫持 + 双重优化 |

## 八、⭐ 核心对比：CHAI（视觉提示注入）vs FGSM（对抗噪声）

这是你今天最该记住的对比：

| 维度 | FGSM（你已跑通） | CHAI（视觉提示注入） |
|------|-----------------|---------------------|
| **攻击对象** | 图像分类器（ResNet） | 具身 AI 的 LVLM（视觉语言模型） |
| **扰动方式** | 修改图片的**每个像素**（加微小梯度噪声） | 在场景里**添加**一块写文字的牌子 |
| **是否改图像** | 改了输入图像本身 | 不改图像，只是"加东西"进场景 |
| **优化方法** | 白盒：`backward()` 拿精确梯度 | 黑盒：交叉熵法（CE method），只看 logits |
| **攻击层级** | 感知层（分类结果错） | 命令层（输出恶意指令文本） |
| **攻击效果** | 模型输出类别改变 | 机器人**执行危险动作** |
| **人眼可见** | 噪声几乎不可见 | 文字人类可读，像广告牌一样显眼 |
| **模型权限** | 需要白盒梯度 | 只需要 API 黑盒查询 |
| **危害传导** | 停留在"识别错误" | 传导到物理世界的动作 |

### 为什么两者互补（你的科研视角）

```
FGSM 攻"输入"： 像素级、连续、白盒、不可见
CHAI 攻"意图"： 语义级、离散、黑盒、人类可读
    ↓
覆盖了 AI 系统两类截然不同的漏洞：
  1. 模型对微小扰动的鲁棒性缺陷（数据面）
  2. 模型对场景语义的过度信任（物理面）
```

你的论文里可以把两条线都写进"威胁模型"章节：
> 我们对 ONNX Runtime 的引擎漏洞做了 fuzz（软件面），同时调研了视觉提示注入
> 对 LVLM 驱动的机器人的威胁（物理面）——两者构成具身 AI 的完整攻击面。

## 九、论文提出的防御（4 条）

1. **过滤/检测可疑文字**：识别画面里"不该出现的指令性文字"
2. **对齐训练**：让 LVLM 学会区分"环境文字"和"真实指令"，不把场景里的字当命令
3. **感知与决策分离**：多智能体架构，让"看"和"决定"分开，中间加验证层
4. **可证明鲁棒性**（provable robustness）方向研究

> 你的启发：**攻击的入口是"文本从视觉进入指令层"**——如果 ONNX 模型加载时也有
> 类似的"信任输入"问题（模型文件本身是数据却被当成代码/信任内容执行），就是同类漏洞。

## 十、给你留的 3 个思考题

1. CHAI 的"通用对抗标牌"和 FGSM 的"通用对抗扰动（universal perturbation）"，
   在思想上是同一种东西吗？区别在哪？
   并不是，chai的通用对抗标牌是攻击的VLM的命令层，也就是他把图片转化成文字后输入命令的时候，攻击篡改这个命令让他输入一些恶意的命令，但是他是黑盒只能用交叉熵统计学来衡量；而FGSN的通用对抗扰动是利用修改VLM的输入图像，添加人肉眼不可见的噪声来混淆VLM的读取图片的能力，他是白盒可以用梯度来衡量
2. 如果一块牌子能劫持 LVLM 机器人，那么一个恶意 `.onnx` 模型文件能不能做同样的事？
   应该不行吧？onnx是软件层也就是底层的代码层，劫持LVLM是通过一些内存泄漏等fuzz出来的漏洞进行的，一块牌子劫持机器人是通过命令层来劫持的，两者不一样
   （想想你的主线 fuzz——两条线的"信任边界"分别在哪）
3. CHAI 用交叉熵法做黑盒优化，为什么不能用 FGSM 的梯度法？（提示：黑盒和白盒的区别）
   CHAI论文指出针对命令层的攻击难以发掘他具体在哪里出错，因为他是模型内部的计算，是黑盒，所以只能用交叉熵等统计学量来衡量，FGSM攻击是白盒，我们可以清楚的看到哪里出错并针对其进行攻击
